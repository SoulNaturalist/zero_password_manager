# Contributing to Zero Password Manager

First off — **thank you** for considering contributing. This is a solo-maintained, non-commercial, open-source project, so every bit of help matters.

## How to Contribute

### 🐛 Reporting Bugs

1. Search [existing Issues](../../issues) to avoid duplicates.
2. If it's new, open an Issue using the **Bug Report** template.
3. Include:
   - Steps to reproduce
   - Expected vs actual behavior
   - Your environment (OS, deployment method, version)

### 💡 Suggesting Features

1. Open an Issue using the **Feature Request** template.
2. Explain the problem it solves and why it fits Zero's philosophy.
3. Be open to discussion — features must align with **self-hosted, zero-knowledge, privacy-first** principles.

### 🔧 Pull Requests

1. Fork the repo and create a feature branch (`feat/my-cool-feature`).
2. Follow the existing code style and folder structure.
3. Write clear commit messages (conventional commits preferred).
4. Update documentation if your change affects user-facing behavior.
5. Open a PR against the `main` branch with a clear description.

### 🧪 Testing

- Backend: `pytest` (FastAPI)
- Client: `flutter test`
- Make sure existing tests pass before submitting.

### 🔒 Security

If you discover a vulnerability, **do not open a public Issue**.
See [SECURITY.md](SECURITY.md) for responsible disclosure.

## Recognition

All contributors are credited in the project README and release notes.
Significant contributors may be invited as collaborators.

Thank you for helping make Zero Password Manager better.
